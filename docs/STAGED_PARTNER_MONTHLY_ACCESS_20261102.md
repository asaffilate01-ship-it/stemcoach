# Staging integration gates — partner access and monthly releases

This draft PR is deliberately **not merged or deployed**. SQL in `docs/staging/` is a reviewed *proposal*, not a Supabase migration. A qualified operator must generate the migration with the Supabase CLI after testing on a clone, run security advisors, and check migration history before applying. No production SQL, Edge Function or pricing configuration is changed here.

The server `check-answer` contains a feature flag `STEMCOACH_PARTNER_ACCESS_ENABLED`. It defaults **OFF** and does not trust the browser, email domain, user metadata or partner name; the service-role-only database function verifies approved tenant membership, institution, course, identity, time window and revocation. On error it fails closed. The staging proposal now includes a transaction-scoped advisory lock and a service-only answer-recording RPC that inserts the attempt under the same lock as the 100-answer UTC daily check. This is **not yet database-tested for concurrent requests**; run load and failure/rollback tests before activation. A separate approval is needed for fair-use terms. The existing free and paid logic remains the fallback.

The tables `stemcoach_monthly_releases`, `stemcoach_monthly_release_items` and `stemcoach_monthly_subscriber_entitlements` are service-only. Monthly releases require a previously approved release containing one or more academically published questions. A Stripe webhook integration is **not built**, so there is currently no paid monthly subscription entitlement. Never expose answer keys with a release manifest. Current one-time packs are unaffected.

**Staging acceptance:** validate exact source IDs (UniPathway internal `unipathways`, `traindirekt`, `skillfinch`), verified/disabled institution and course, student course transfer, expiration, revocation, wrong tenant, content subject/curriculum mismatch, 100/day quota under simultaneous requests (including 101 parallel attempts), transaction rollback on failed inserts, credential-leak checks, billing refund and chargeback, monthly release withdrawal, missing webhook and failed provider. Add a signed partner enrolment sync, authorization on question-read endpoints, server quota receipt, client partner-status mirror and independent financial approval before deployment. Implement approved subscriptions only after production-price and payment-contract review.

No changes to live RLS, no student records read, no external provider activated, no Lovable credits.
