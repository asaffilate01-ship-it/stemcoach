# Learner-controlled coaching actions: design and integration review

Reviewed 27 November 2026. Use the existing PRODUCT.md and DESIGN.md, not a third-party visual identity. The aim is to move a learner from a tutoring explanation to an actual practice activity without losing work or allowing a model to execute a hidden action.

## Reference patterns and decisions

| Reference | Useful pattern | STEMCoach decision |
| --- | --- | --- |
| [OpenAI Agents SDK](https://github.com/openai/openai-agents-js) | Bounded tools, guardrails, human approval and traces | Expose explicit learner-initiated actions from a deterministic route registry. Do not let a model emit arbitrary navigation, publish or grade commands. |
| [Claude Agent SDK](https://github.com/anthropics/claude-agent-sdk-typescript) | Narrow permission scope and controlled tool access | Keep existing opt-in server-approved provider transport and do not grant the tutor a shell or direct database credentials. |
| [Google ADK for TypeScript](https://github.com/google/adk-js) | Typed orchestration and schema validation | Validate subject and lesson context against supported authored IDs. Retain simple local navigation; no agent dependency is needed for this task. |
| [Qwen-Agent](https://github.com/QwenLM/Qwen-Agent) | Tool calling and retrieval-assisted answers | Keep future retrieval grounded in reviewed resources, with external access separately authorised; do not execute the framework's example code interpreter in a learner session. |
| [MCP security guidance](https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/security_best_practices) | Per-client consent, narrow scopes and token/redirect protections | Future MCP connections need an authenticated server broker, explicit tool schemas, destination allowlist, tenant checks and consent. No external MCP server is activated in this release. |
| [Impeccable](https://github.com/pbakaus/impeccable) and [WCAG target-size guidance](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | Audit usability, accessibility, responsive hierarchy and touch controls | Place a labelled study action region before the chat workspace, wrap controls at small widths, use existing semantic tokens and aim for 44px touch controls. Respect reduced-motion preference. |

## Implemented in this phase

- Contextual routes for Q&A, due reviews, previous mistakes, subject practice and authored lesson navigation; existing weak-topic access retained.
- The route registry accepts only supported subject identifiers and matching authored lesson identifiers. It never consumes URLs generated by a model.
- During an active request or nonempty draft, switching via these tutor controls is blocked and the reason is shown. The learner may clear/edit their own draft, submit it, or stop a response. No draft is automatically sent or saved by navigation actions.
- Existing account-scoped device revision filters remain authoritative; no learner identity, private history or transcript is included in the route.
- English/German/French translation entries. Active locale/launch restrictions remain unchanged.
- Deterministic routing tests and UI interaction coverage. CI must validate this change; code-level review does not equal manual device or assistive technology certification.

## Deferred

Do not add provider SDKs merely for feature parity. An externally executing tutor agent requires a threat model, authorised tools, safe inputs/outputs, cost limits, evaluation, red-team fixtures, child-data controls and staging deployment. This release neither executes autonomous agents nor enables new provider keys. Formal exam grading, publication and billing remain subject to separate database release gates.
